# 架构分析

对项目或指定模块进行全面的架构健康度分析。

## 用法

```
/analyze                     # 全项目分析
/analyze src/core             # 分析 CLI 核心模块
/analyze src/content/rules    # 分析规范规则
```

## 分析维度

### 1. 目录职责边界（权重 30%）
- 检查 `src/` 是否只包含代码文件
- 检查 `src/content/` 是否只包含规范文件（无代码逻辑）
- 检查 `src/content/` 中的文件是否技术栈无关（无硬编码框架引用）
- 检查 `src/presets/` 中各预设是否自包含（有 preset.json）
- 检查模块依赖方向是否合规

### 2. 代码复杂度（权重 20%）
- 文件行数超过 300 行的文件
- 函数体超过 40 行的函数
- 参数超过 4 个的函数
- 嵌套深度超过 3 层的代码块

### 3. 测试覆盖（权重 20%）
- 统计各模块有对应 `.test.` 文件的源文件比例
- 识别无测试的业务逻辑文件（非 types / index）
- 检查测试文件命名规范

### 4. 依赖健康度（权重 15%）
- 检查 package.json 中是否有未使用的依赖
- 检查是否有功能重叠的依赖
- 检查核心依赖版本是否过时

### 5. 文档同步（权重 15%）
- 检查 CLAUDE.md 目录结构是否与实际一致
- 检查 docs/ARCHITECTURE.md 模块列表是否最新
- 检查 ADR 是否有废弃但仍被引用的记录
