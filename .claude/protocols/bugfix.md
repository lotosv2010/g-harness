# Bug 修复协议

> 当用户报告"Bug"、"出错"、"不工作"、"异常"时，遵循本协议。

---

## 阶段 1：复现与定位

**必做：**
1. 确认 Bug 的具体表现（错误信息、截图、复现步骤）
2. 定位问题代码（使用 Grep、Read 搜索相关代码）
3. 分析根因（不是表面症状）
4. 检查是否有相关的测试用例

**输出：**
- Bug 根因分析
- 受影响的文件列表
- 是否涉及其他模块的连锁影响

## 阶段 2：修复方案

**必做：**
1. 提出修复方案
2. 评估修复的影响范围
3. 说明是否需要数据迁移或配置变更

**原则：**
- 最小修改原则：只改必须改的
- 不在修复中夹带重构
- 不改变无关代码的行为

## 阶段 3：修复 + 回归测试

**必做：**
1. 编写回归测试（先写测试，确认能复现 Bug）
2. 应用修复
3. 确认回归测试通过
4. 确认现有测试不受影响

## 阶段 4：验证

**必做：**
1. 运行完整测试套件
2. 类型检查
3. lint 检查

**输出：**
- 修复摘要
- 根因说明
- 回归测试说明
