# API 设计协议

> 当用户请求"设计 API"、"新增接口"、"API 规划"、"接口设计"时，遵循本协议。

---

## 阶段 1：需求梳理

**必做：**
1. 阅读 `docs/API.md`（如存在）确认现有 API 风格和约定
2. 阅读 `docs/ARCHITECTURE.md` 确认架构约束
3. 明确 API 消费者（前端 / 移动端 / 第三方 / 内部服务）
4. 明确功能边界：
   - 这组 API 要解决什么问题
   - 涉及哪些资源/实体
   - 是否有现有 API 可复用或扩展

**输出：**
- API 需求摘要
- 资源列表
- 消费者说明
- 约束和限制

## 阶段 2：契约设计

**必做：**
1. 设计 API 契约，遵循 RESTful 或项目既有风格：

```markdown
### [HTTP Method] [Path]

**描述**：[功能说明]

**请求参数**：
| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|

**请求体**（如有）：
```json
{}
```

**响应**：
| 状态码 | 说明 | 响应体 |
|--------|------|--------|

**错误码**：
| 错误码 | 含义 | HTTP 状态 |
|--------|------|----------|
```

2. 设计通用规范：
   - 认证方式
   - 分页约定
   - 错误响应格式
   - 版本策略

3. 将契约写入 `docs/API.md`

**输出：**
- API 契约文档（等待用户确认）

**禁止：** 未确认契约就开始实现

## 阶段 3：实现

**必做：**
1. 按确认的契约实现 API
2. 遵循 `.claude/rules/` 中的所有规则
3. 实现层级分离：
   - 路由层（接收请求、参数校验）
   - 业务层（核心逻辑）
   - 数据层（数据访问）
4. 输入校验：
   - 类型校验
   - 边界值校验
   - 必填项校验
5. 同步编写测试：
   - 正常路径测试
   - 边界值测试
   - 错误处理测试
   - 认证/授权测试（如有）

**禁止：**
- 路由层包含业务逻辑
- 跳过输入校验
- 跳过测试

## 阶段 4：验证

**必做：**
1. `pnpm typecheck` — 类型检查通过
2. `pnpm test` — 全量测试通过
3. `pnpm lint` — 代码检查通过
4. API 契约与实现一致性检查

**输出：**
- 实现变更摘要
- 测试覆盖情况
- API 文档是否同步

## 阶段 5：文档

**必做：**
1. 确认 `docs/API.md` 与实现一致
2. 如涉及数据模型变更 → 更新 `docs/DATA_MODEL.md`
3. 如涉及架构变更 → 新增 ADR

**完成标志：** API 实现 + 测试通过 + 契约文档同步
