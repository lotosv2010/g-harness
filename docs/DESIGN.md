# 技术 / UI 设计文档

> 记录 G-Forge 的技术设计决策和界面设计规范。
> AI 在做设计类决策时参考本文件。

---

## 1. CLI 交互设计

### 1.1 输出风格

- 使用 picocolors 进行终端着色
- Error 红色、Warning 黄色、Success 绿色、Info 灰色
- 标题使用 bold，辅助信息使用 dim
- 进度类信息使用 emoji 前缀（`🔍`、`✓`、`⚠️`）

### 1.2 命令结构

```
gforge <command> [options]

命令层级不超过两层：
  gforge init         # 一级命令
  gforge context sync # 二级命令（子命令）
```

### 1.3 退出码

| 退出码 | 含义 |
|--------|------|
| 0 | 成功 |
| 1 | 校验失败 / 执行错误 |
| 2 | 参数错误 |

## 2. 规范文件设计

### 2.1 模板变量语法

采用 `{{variable_name}}` 双花括号语法：
- 变量名仅限 `\w+`（字母、数字、下划线）
- 未匹配的变量保留原样，不报错
- 变量值来源优先级：预设变量 > 扫描推断 > 默认值

### 2.2 规则 ID 命名规范

| 前缀 | 含义 | 示例 |
|------|------|------|
| R | 通用代码规则 | R001 严格类型 |
| A | 架构规则 | A003 API 层集中 |
| S | 安全规则 | S001 敏感信息保护 |

### 2.3 预设结构规范

```
src/presets/<name>/
├── preset.json       # 元数据（必需）
├── rules/            # 栈特定规则（可选）
└── skills/           # 栈特定技能（可选）
```

## 3. 技术设计

### 3.1 模块依赖方向

```
cli → core → utils
          ↘ content (规范文件，仅读取)
          ↘ presets (预设文件，仅读取)
          ↘ templates (模板文件，仅读取)
```

代码只能向右依赖，禁止反向依赖。

### 3.2 文件生成策略

| 场景 | 行为 |
|------|------|
| 目标文件不存在 | 创建 |
| 目标文件已存在 + 无 `--force` | 跳过 |
| 目标文件已存在 + `--force` | 覆盖 |
| `--dry-run` | 仅打印文件列表，不写入 |
