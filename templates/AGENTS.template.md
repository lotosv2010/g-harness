# AGENTS.md — 通用 AI 开发规范

> 由 G-Forge 生成。定义所有 AI 编程助手共同遵守的开发规范。
> 与具体 AI 工具无关，是团队与 AI 协作的基础契约。

---

## 1. 核心原则

### 1.1 先理解，再动手

```
正确流程：读上下文 → 理解架构 → 确认方案 → 编写代码
错误流程：直接开写 → 遇到问题 → 推倒重来
```

AI 在执行任何代码变更前，必须：
1. 读取当前目录及上级目录的上下文文件
2. 读取相关的架构决策记录
3. 识别受影响的模块和依赖关系
4. 确认要遵循的模式和约定

### 1.2 最小变更原则

- 只修改完成任务所需的最少文件
- 不做"顺便"的重构，除非明确要求
- 不引入当前不需要的依赖
- 不改变现有代码的行为，除非这就是目标

### 1.3 可验证性原则

- 每个变更必须可测试
- 每个决策必须可追溯
- 每个新增模式必须有示例

## 5. Git 规范

### 5.1 提交消息

格式：`<type>(<scope>): <description>`

有效的 type：
- `feat` — 新功能
- `fix` — Bug 修复
- `refactor` — 重构
- `docs` — 文档
- `test` — 测试
- `chore` — 杂项

## 6. AI 协作安全规则

### 6.1 禁止事项

- **禁止**提交 `.env` 文件或任何包含密钥的文件
- **禁止**在代码中硬编码密钥、Token、密码
- **禁止**未经确认执行破坏性操作
- **禁止**修改 CI/CD 配置而不说明原因
- **禁止**绕过 pre-commit 钩子

### 6.2 需确认事项

以下操作必须先向用户确认：
- 删除文件或目录
- 修改数据库 Schema
- 升级核心依赖版本
- 修改构建或部署配置
- 向第三方服务发送数据

---

## 7. 文档维护

- 注释语言与代码库现有注释保持一致
- 只注释"为什么"，不注释"是什么"
- 公共 API 必须有类型标注文档
- 代码变更涉及架构时，必须同步更新相关文档
