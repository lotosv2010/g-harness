# 功能开发协议

> 当用户请求"添加功能"、"实现功能"、"新增模块"时，遵循本协议。

---

## 阶段 1：理解需求

**必做：**
1. 阅读项目的任务追踪文件，确认当前上下文
2. 阅读产品文档，确认功能在范围内
3. 阅读架构文档，确认技术约束
4. 阅读目标目录的上下文文件（如存在）
5. 检查架构决策记录中是否有相关 ADR

**输出：**
- 简要复述需求理解
- 列出将要创建/修改的文件
- 识别要遵循的模式和约定
- 提出疑问（如有）

## 阶段 2：方案确认

**必做：**
1. 提出实现方案（不超过 3 个备选）
2. 说明每个方案的优劣
3. 推荐一个方案并说明理由
4. 等待用户确认后再开始编码

**禁止：**
- 未确认方案就开始写代码
- 提出超出需求范围的扩展建议

## 阶段 3：实现

**必做：**
1. 按照确认的方案编码
2. 遵循项目规则文件中的所有规则
3. 遵循 AI 规范中的编码约定
4. 同步编写测试
5. 更新相关的入口文件

**禁止：**
- 修改需求范围外的文件
- 引入未讨论的新依赖
- 跳过测试

## 阶段 4：验证

**必做：**
1. 运行类型检查
2. 运行测试
3. 运行代码检查
4. 检查是否有架构规则违规

**输出：**
- 变更摘要（创建了哪些文件、修改了哪些文件）
- 测试结果
- 已知限制或待办事项

## 阶段 5：文档（按需）

如果变更涉及以下内容，必须同步更新文档：
- 新增模块 → 更新架构文档模块部分
- 新增 API → 更新 API 规格文档
- 数据模型变更 → 更新数据模型文档
- 架构级决策 → 新增 ADR
