# API 设计协议

> 当用户请求"设计 API"、"新增接口"、"API 规划"、"接口设计"时，遵循本协议。
> 每个阶段完成后，在回复中标记 `[✓ 阶段N]`，Stop hook 会验证是否遗漏。

---

## 检查清单

### 阶段 1：需求梳理
- [ ] 确认现有 API 风格和约定
- [ ] 确认架构约束
- [ ] 明确 API 消费者（前端 / 移动端 / 第三方 / 内部服务）
- [ ] 明确功能边界和涉及资源
- [ ] 检查是否有现有 API 可复用或扩展

**完成标志：** `[✓ 阶段1-需求梳理]`

### 阶段 2：契约设计
- [ ] 设计 API 端点和参数
- [ ] 设计请求/响应格式
- [ ] 设计错误码体系
- [ ] 设计通用规范（认证、分页、版本策略）
- [ ] 将契约写入 API 文档

**完成标志：** `[✓ 阶段2-契约设计]`

**禁止：** 未确认契约就开始实现

**API 端点设计模板：**

```markdown
### [HTTP Method] [Path]

**描述**：[功能说明]

**请求参数**：
| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|

**请求体**（如有）：
json {}

**响应**：
| 状态码 | 说明 | 响应体 |
|--------|------|--------|

**错误码**：
| 错误码 | 含义 | HTTP 状态 |
|--------|------|----------|
```

### 阶段 3：实现
- [ ] 按确认的契约实现 API
- [ ] 遵循规则文件中的所有规则
- [ ] 实现层级分离（路由层 / 业务层 / 数据层）
- [ ] 实现输入校验（类型、边界值、必填项）
- [ ] 同步编写测试（正常路径、边界值、错误处理、认证）

**完成标志：** `[✓ 阶段3-实现]`

**禁止：** 路由层包含业务逻辑；跳过输入校验；跳过测试

### 阶段 4：验证
- [ ] 类型检查通过
- [ ] 全量测试通过
- [ ] 代码检查通过
- [ ] API 契约与实现一致性检查

**完成标志：** `[✓ 阶段4-验证]`

### 阶段 5：文档
- [ ] API 文档与实现一致
- [ ] 如涉及数据模型变更，更新数据模型文档
- [ ] 如涉及架构变更，新增 ADR

**完成标志：** `[✓ 阶段5-文档]` 或 `[✓ 阶段5-无需文档更新]`
