# 部署协议

> 当用户请求"发布"、"上线"、"部署"、"灰度"、"回滚"时，遵循本协议。
> 每个阶段完成后，在回复中标记 `[✓ 阶段N]`，Stop hook 会验证是否遗漏。

---

## 检查清单

### 阶段 1：准备度评估
- [ ] 确认本次发布内容（变更清单 + 对应 FR/Bug ID）
- [ ] 检查 CI 状态（全部 green）
- [ ] 检查是否有未解决的阻塞 Issue
- [ ] 检查是否需要数据库迁移 / 配置变更
- [ ] 检查是否需要依赖服务升级

**完成标志：** `[✓ 阶段1-准备度]`

**禁止：** CI 未通过或存在未处理阻塞时强行发布

### 阶段 2：风险与回滚计划
- [ ] 评估变更风险（低 / 中 / 高）
- [ ] 明确回滚触发条件（错误率、P99 延迟、业务指标）
- [ ] 明确回滚步骤（版本切换 / 数据回滚 / 配置恢复）
- [ ] 确认灰度策略（百分比 / 用户白名单 / 地域）
- [ ] 通知相关干系人（谁需要知道？谁需要随时响应？）

**完成标志：** `[✓ 阶段2-风险]`

### 阶段 3：执行部署
- [ ] 按照 `docs/runbooks/` 对应 runbook 执行
- [ ] 每一步可观察：部署开始 / 节点就绪 / 流量切换 / 指标稳定
- [ ] 实时监控关键指标（错误率、延迟、吞吐、核心业务指标）
- [ ] 遇到回滚条件立即执行回滚，不犹豫

**完成标志：** `[✓ 阶段3-执行]`

**原则：** 发布期间不做其他变更；如遇异常，先回滚再定位

### 阶段 4：验证与观察
- [ ] 冒烟测试关键路径
- [ ] 对比发布前后核心指标（30 分钟以上窗口）
- [ ] 检查日志是否有新型错误
- [ ] 检查依赖服务是否正常
- [ ] 确认客户可达性（多地域 / 多客户端）

**完成标志：** `[✓ 阶段4-验证]`

### 阶段 5：收尾
- [ ] 更新发布记录（版本号 + 变更点 + 时间）
- [ ] 关闭相关 Issue / Task
- [ ] 如有回滚，输出回滚事后总结
- [ ] 更新 `docs/runbooks/` 中过期的操作步骤

**完成标志：** `[✓ 阶段5-收尾]`
