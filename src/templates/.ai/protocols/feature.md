# 功能开发协议

> 当用户请求"添加功能"、"实现功能"、"新增模块"时，遵循本协议。
> 每个阶段完成后，在回复中标记 `[✓ 阶段N]`，Stop hook 会验证是否遗漏。

---

## 检查清单

### 阶段 1：理解需求
- [ ] 阅读任务追踪文件，确认当前上下文
- [ ] 阅读产品文档，确认功能在范围内
- [ ] 阅读架构文档，确认技术约束
- [ ] 检查相关 ADR 决策记录
- [ ] 复述需求理解并列出将要变更的文件

**完成标志：** `[✓ 阶段1-需求理解]`

### 阶段 2：方案确认
- [ ] 提出实现方案（不超过 3 个备选）
- [ ] 说明每个方案的优劣
- [ ] 推荐方案并说明理由
- [ ] 等待用户确认后再编码

**完成标志：** `[✓ 阶段2-方案确认]`

**禁止：** 未确认方案就开始写代码

### 阶段 3：实现
- [ ] 按确认方案编码
- [ ] 遵循规则文件中的所有规则
- [ ] 遵循 AI 规范中的编码约定
- [ ] 同步编写测试
- [ ] 更新相关入口文件

**完成标志：** `[✓ 阶段3-实现]`

**禁止：** 修改需求范围外的文件、引入未讨论的依赖、跳过测试

### 阶段 4：验证
- [ ] 运行类型检查
- [ ] 运行测试
- [ ] 运行代码检查
- [ ] 检查架构规则违规

**完成标志：** `[✓ 阶段4-验证]`

### 阶段 5：文档（按需）
- [ ] 新增模块 → 更新架构文档
- [ ] 新增 API → 更新 API 规格文档
- [ ] 数据模型变更 → 更新数据模型文档
- [ ] 架构级决策 → 新增 ADR

**完成标志：** `[✓ 阶段5-文档]` 或 `[✓ 阶段5-无需文档更新]`
