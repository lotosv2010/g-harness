# 测试计划协议

> 当用户请求"制定测试计划"、"补测试"、"测试覆盖"、"写回归测试"时，遵循本协议。
> 每个阶段完成后，在回复中标记 `[✓ 阶段N]`，Stop hook 会验证是否遗漏。

---

## 检查清单

### 阶段 1：目标定义
- [ ] 明确测试目标（功能验收 / 回归防护 / 性能基线 / 契约测试）
- [ ] 读 `docs/FEATURES.md` 确认被测功能的入口与相关文件
- [ ] 读 `docs/SPEC.md` 对应 FR/NFR 条款
- [ ] 查阅现有测试覆盖（是否已有同类用例）

**完成标志：** `[✓ 阶段1-目标]`

### 阶段 2：测试分层设计
- [ ] 列出单元测试范围（纯函数 / 类方法 / Hook）
- [ ] 列出集成测试范围（跨模块协作 / IO 边界）
- [ ] 列出端到端测试范围（用户路径 / 关键链路）
- [ ] 标注每层的**覆盖率目标**与**执行频率**

**完成标志：** `[✓ 阶段2-分层]`

**原则：** 测试金字塔 — 单元 > 集成 > E2E；不盲目追求 100% 覆盖率

### 阶段 3：用例清单
- [ ] 正常路径（Happy Path）
- [ ] 边界值（空/最大/最小/零）
- [ ] 异常路径（无效输入、网络错误、并发冲突）
- [ ] 不变式（数据一致性、权限隔离）
- [ ] 每个用例标注：输入 / 执行 / 断言

**完成标志：** `[✓ 阶段3-用例]`

**禁止：** 仅覆盖 happy path、缺失异常路径测试

### 阶段 4：实现与运行
- [ ] 按用例清单实现测试
- [ ] 确认每个用例可独立运行（无顺序依赖）
- [ ] Mock 边界清晰（仅 Mock 外部依赖，不 Mock 被测单元）
- [ ] 运行测试套件并收集覆盖率数据

**完成标志：** `[✓ 阶段4-实现]`

### 阶段 5：评审与并入 CI
- [ ] 输出覆盖率报告（对比目标）
- [ ] 识别未覆盖的关键分支
- [ ] 决定是否补测或记录为已知风险
- [ ] 确认测试已并入 CI pipeline

**完成标志：** `[✓ 阶段5-评审]`
