# 数据/Schema 迁移协议

> 当用户请求"数据迁移"、"Schema 变更"、"数据库变更"、"接口升级"、"破坏性变更"时，遵循本协议。
> 每个阶段完成后，在回复中标记 `[✓ 阶段N]`，Stop hook 会验证是否遗漏。

---

## 检查清单

### 阶段 1：影响分析
- [ ] 确认当前数据结构（阅读数据模型文档）
- [ ] 确认受影响的接口（阅读 API 文档）
- [ ] 评估影响范围（表/集合/文件、API 端点、下游消费者）
- [ ] 判断变更类型（向后兼容 / 需迁移 / 破坏性）
- [ ] 评估数据量（影响迁移策略）

**完成标志：** `[✓ 阶段1-影响分析]`

**禁止：** 未完成影响分析就开始写迁移代码

### 阶段 2：迁移方案设计
- [ ] 选择迁移策略（蓝绿切换 / 渐进迁移 / 一次性迁移）
- [ ] 设计正向迁移（up）
- [ ] 设计回滚迁移（down）
- [ ] 设计数据校验（verify）
- [ ] 确保幂等性（重复执行不报错）
- [ ] 如涉及 API 变更，设计版本过渡方案

**完成标志：** `[✓ 阶段2-方案设计]`

**禁止：** 未确认迁移方案就开始实现

### 阶段 3：实现
- [ ] 实现迁移脚本（确保幂等）
- [ ] 实现回滚脚本
- [ ] 更新受影响的业务代码
- [ ] 遵循规则文件中的所有规则
- [ ] 编写测试：迁移正向 + 回滚 + 业务兼容性

**完成标志：** `[✓ 阶段3-实现]`

**禁止：** 没有回滚方案的迁移；跳过迁移测试

### 阶段 4：验证
- [ ] 类型检查通过
- [ ] 全量测试通过
- [ ] 迁移脚本干跑（dry-run）验证
- [ ] 回滚脚本验证

**完成标志：** `[✓ 阶段4-验证]`

### 阶段 5：文档更新
- [ ] 更新数据模型文档
- [ ] 更新 API 文档（如涉及接口变更）
- [ ] 高风险变更写入 ADR
- [ ] 如需运维操作，写入运维手册

**完成标志：** `[✓ 阶段5-文档]` 或 `[✓ 阶段5-无需文档更新]`
