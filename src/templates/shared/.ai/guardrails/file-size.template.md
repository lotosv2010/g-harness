# 文件体积守卫 — {{project_name}}

> 防止单文件过大，促进模块化拆分。

---

## 阈值规则

| 指标 | 警告阈值 | 阻塞阈值 | 说明 |
|------|----------|----------|------|
| 文件行数 | >200 行 | >300 行 | 源代码文件（不含测试） |
| 函数行数 | >30 行 | >50 行 | 单个函数/方法 |
| 函数参数 | >3 个 | >5 个 | 考虑使用 options 对象 |
| 文件体积 | >50KB | >100KB | 二进制/资源文件除外 |

## 豁免规则

以下文件不受行数限制：
- 测试文件（`*.test.*` / `*.spec.*`）
- 类型声明文件（`*.d.ts`）
- 自动生成文件（带 `@generated` 注释）
- 配置文件（`*.config.*`）
- 数据文件（`*.json` / `*.yaml`）

## 触发时机

- **pre-commit hook：** 检查本次提交涉及的文件
- **CI pipeline：** 全量扫描，输出超阈值文件清单
- **AI 辅助开发：** 每次新建/修改文件后自动检查

## 处理建议

文件超限时考虑：
1. 提取公共逻辑为独立模块
2. 将数据常量移至配置文件
3. 按功能职责拆分为多个文件
4. 检查是否有重复代码可抽象
