# 测试覆盖率门禁守卫 — {{project_name}}

> 确保关键代码路径有测试覆盖，防止覆盖率持续下降。

---

## 覆盖率阈值

| 维度 | 最低要求 | 建议目标 | 说明 |
|------|----------|----------|------|
| 行覆盖率 | ≥70% | ≥85% | 全局代码行覆盖 |
| 分支覆盖率 | ≥60% | ≥80% | 条件分支覆盖 |
| 函数覆盖率 | ≥80% | ≥90% | 公共函数覆盖 |
| 增量覆盖率 | ≥80% | ≥90% | 本次变更的新增代码 |

## 规则

### 阻塞规则（CI 失败）

- 增量覆盖率低于 80%（新代码未充分测试）
- 全局覆盖率较上次发布下降超过 2%

### 警告规则（不阻塞但标注）

- 全局覆盖率低于建议目标
- 存在无任何测试的公共模块
- 关键路径（支付、认证、数据持久化）覆盖率 <90%

## 豁免目录

以下目录不计入覆盖率统计：
- 类型声明（`types/` / `*.d.ts`）
- 配置文件（`*.config.*`）
- 脚手架/模板文件
- 第三方集成 mock

## 集成方式

```bash
# Vitest 示例
vitest run --coverage --coverage.thresholds.lines=70 --coverage.thresholds.branches=60

# Jest 示例
jest --coverage --coverageThreshold='{"global":{"lines":70,"branches":60}}'
```

## 覆盖率提升策略

当覆盖率不达标时优先补充：
1. 核心业务逻辑的正向路径测试
2. 错误处理和边界条件
3. 公共工具函数
4. 用户可感知的功能端到端流程
